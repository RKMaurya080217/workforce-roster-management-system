3. ROOT CAUSE & ARCHITECTURAL FIX SUMMARY
--------------------------------------------------------------------------------
[ROOT CAUSE IDENTIFIED]
Previously, the Profile Request Change workflow was disconnected in several critical places:
1. When employees changed a profile field inline (e.g. mobile number) and clicked "Request Change",
   the handler submitted directly via `submitDirectProfileChange(...)` without opening a confirmation dialog
   and without collecting a mandatory reason/justification from the employee.
2. The Request Change modal (`#profileChangeModal`) lacked a Reason for Change input, an explicit confirmation alert,
   and did not display request reference IDs.
3. The Employee Profile Change Requests table lacked columns for "Request ID" and "Reason", hiding the justification.
4. The Admin unified approval dashboard Reason column defaulted to `'Pending admin review'` because `r.reason`
   was not mapped on `ProfileChangeRequest` entity or returned in `ProfileChangeRequestResponse`.
5. Reviewer identity (`decided_by`) was not recorded on profile approval/rejection.
6. Approval did not trigger canonical CSV synchronization via `EmployeeMasterSyncService`.

[IMPLEMENTATION FIXES]
1. Domain Entity & DTO Mapping:
   - Mapped `request_reason VARCHAR(1000)` and `decided_by VARCHAR(100)` onto `ProfileChangeRequest.java`.
   - Updated `CreateProfileChangeRequest.java` to support `reason` with backward-compatible 2-argument constructor.
   - Updated `ProfileChangeRequestResponse.java` to include `reason` and `reviewedBy` with backward-compatible constructor.
2. Service & Approval Workflow:
   - Updated `ProfileChangeRequestService.java`:
     * Saves employee's reason on submission.
     * Records reviewer identity from authenticated `SecurityContextHolder` on approval and rejection.
     * Re-validates requested values upon approval before mutating employee master data.
     * Atomically synchronizes canonical CSV (`EmployeeMasterSyncService`) and dev mirror on approval.
     * Generates in-app notifications (`PROFILE_CHANGE_DECISION`) and audit logs.
     * Added `getAllRequests(status, employeeId)` with filtering support.
3. Admin Endpoints:
   - Added `GET /api/admin/profile-change-requests` with `status` and `employeeId` filters.
   - Added `GET /api/admin/profile-change-requests/history`.
4. Frontend UI Enhancements:
   - Added `#pcrFormReason` textarea and confirmation banner to `#profileChangeModal` in `index.html`.
   - Updated `handleProfileChangeClick` in `app.js` to always present modal confirmation and capture reason.
   - Enhanced `renderMyChangeRequestsTableHTML` with full 9-column specification (Request ID, Field, Current Value,
     Requested Value, Reason, Submitted At, Status, Reviewed At, Admin Remarks).
   - Displayed employee's reason in `renderProfileApprovalsCategoryBody` for Admin review.
   - Updated client distribution launcher `run.bat` to detect `WRMS-Client-1.0.8.jar`.
